Routing

Routes are declared in a c.routes() block. Each method helper takes a pattern and a block: c.get, c.post, c.put, c.patch, c.delete, plus c.head, c.options and c.any.

fn app(c: web::Ctx&) {
    c.routes() {
        c.get("/") { c.text("home"); };
        c.get("/users/:id") { c.text(c.param("id")); };
        c.post("/users") { c.no_content(); };
    };
}
The routes block runs twice. The first pass only matches patterns, and the second runs the body of the one route that matched. Keep the block declarative: route calls, groups, and functions that declare routes. Do not branch on mutable state inside it, and do not put side effects there.

A path that matches but has the wrong method gets 405 method_not_allowed with an Allow header. A path that matches nothing gets 404 not_found. Path matching is exact: case, trailing slashes and encoded bytes all count.

Groups

c.group("/api/v1") {
    c.get("/status") { c.text("ok"); };      // GET /api/v1/status
};

Path parameters

A segment written :name matches one nonempty segment and is not percent-decoded. Typed accessors check the value and write 422 invalid_param when it does not fit:

CallAccepts
c.param(name)the raw segment
c.param_int(name)a signed integer
c.param_u64(name)a canonical unsigned 64-bit decimal
c.param_uuid(name)8-4-4-4-12 hex, all lower or all upper case, returned as sent
c.param_slug(name)1 to 64 bytes of a-z, 0-9 and -

A final segment written *name takes the rest of the path, slashes included, so c.get("/files/*path") matches /files/a/b.txt with c.param("path") == "a/b.txt".

Host scopes

c.host("api.example.com") { ... } and c.host("*.example.com") { ... } limit the routes inside them to one Host header. The port is ignored and the comparison ignores ASCII case. A request without a Host header matches only unscoped routes.

Typed bindings are called as plain functions, not as methods. Missing keys keep the defaults declared on the struct.

struct Search { limit: i32 = 10, q: u8[..32] = "", active: bool = false }

c.get("/search") {
    let s, ok = query<Search>(c);     // called as a plain function
    guard ok else { return; }           // 400 invalid_query is already written
    c.json(s);
};
struct NewTodo { title: u8[..64] = "" }

c.post("/todos") {
    let form_value, ok = form<NewTodo>(c);
    guard ok else { return; }           // 415 or 400 invalid_form is already written
    c.redirect("/", web::HTTP_SEE_OTHER);
};

body<T> fails with these responses, already written for you:

FailureStatusCode
Media type is not application/json415unsupported_media_type
Empty body, or not JSON400invalid_json
Wrong field type, unknown key, out-of-range value422invalid_payload

Use body_result<T> when a PATCH handler needs to know which fields were sent: has<T>(result, "field").

Responses

CallWrites

c.json(value)a struct or scalar as application/json, keeping the status already set
c.json_list(items)an array or slice as a JSON array
c.text(s), c.html(s), c.json_raw(s)a body with its content type
c.html_template(src, data)a compiled template as HTML (see Features)

Bodies are capped by max_response_bytes (1 MiB by default, 16 MiB at most). A larger body becomes a complete 500 response_too_large rather than a truncated response. Responses are serialized into a bounded pool, so a response that does not fit is refused with 503.

Middleware

Middleware wraps the routes it contains. A middleware function takes the Next type parameter and calls it where the inner work should run. Code before Next() runs on the way in, code after it runs on the way out, and not calling Next() stops the request:

fn timed<Next>(c: web::Ctx&) {
    c.set("X-Served-By", "goose-web");   // before: runs first
    Next();                              // the routes and inner middleware run here
    // after: runs last, even when a handler refused the request
}

fn app(c: web::Ctx&) {
    request_id(c) { c.logger() { timed(c) {
        c.routes() { c.get("/") { c.text("hi"); }; };
    }}};
}

The built-in middleware:

CallBehavior
request_id(c) { }sets X-Request-ID from a process-wide counter
logger(c) { }prints one line per response: method, path, status and bytes
cors(c, origin = "*") { }sets Access-Control-Allow-Origin and answers preflight requests with 204
require_json(c) { }415 unless the request's media type is application/json
secure_headers(c, csp, hsts) { }nosniff, DENY framing, a referrer policy, a Content-Security-Policy, and HSTS when given
rate_limit(c, limit, window_ms) { }fixed window per client address; 429 with Retry-After
session(c, config) { }, csrf(c, secret) { }signed sessions and CSRF checks; see Features
c.static_files(prefix, dir) { }serves files under a URL prefix; see the static-file contract in the API reference
Order matters. Put request_id and logger outside the other middleware so every response, including refusals, gets an ID and a log line. Wrap the /docs page in a secure_headers policy that allows the Swagger UI assets; the starter shows one.

rate_limit keys on c.peer(). Behind a reverse proxy every client shares the proxy's address, so limits do not separate users there; limits are per process, not shared between instances.

Errors

Application errors share one shape, and the built-in refusals use the same one:

{"error":{"code":"not_found","message":"Route not found"}}

Unknown routes answer 404 not_found, wrong methods 405, and protocol violations are plain text and close the connection. Write your own with c.fail(status, code, message); the codes you choose become part of your API, so document them with the route (the OpenAPI helpers do this, see Features).
