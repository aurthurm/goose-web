Goose Web

An HTTP framework for the Goose programming language. Typed routes, reflective JSON, templates compiled into your program, signed sessions, CSRF protection, OpenAPI generation, a SQLite layer and server-sent events, on a nonblocking readiness loop.

Experimental. Linux is tested and macOS is not yet verified. The transport is POSIX-only, and TLS and streamed request bodies are not implemented. The roadmap lists what is planned.

A complete program

This is the whole server: one health route, request IDs and access logs, and port selection from the command line.

import goose_web from "aurthurm/goose-web@v0.6.0";
import std;
import os;

struct Health { status: u8[..8] }

fn app(c: web::Ctx&) {
    request_id(c) { c.logger() {
        c.routes() {
            c.get("/health") { c.json(Health { status: "ok" }); };
        };
    }};
}

fn main() {
    let config, ok, error = web::config_from_args(args());
    if !ok { abort(error); }
    let started = web::run(config) { c => app(c) };
    if !started { abort("server failed"); }
}

Build and run it with goose run server.goose -- 8080, or goose build server.goose. The getting started guide covers the package declaration, the starter project and the local-checkout form to use until a release tag exists.

What is included

  • Routing: method helpers, :param and *wildcard segments, groups, host scopes, typed path parameters, automatic 404 and 405 with Allow.
  • Data: strict JSON bodies and responses, typed query strings and forms, cookies.
  • Middleware: request IDs, logging, CORS, JSON checks, security headers, per-client rate limits, and your own middleware in the same shape.
  • Security: HMAC-signed cookie sessions and double-submit CSRF tokens, using native SHA-256, HMAC and a CSPRNG.
  • Documentation: an OpenAPI 3.1 document generated from the routes, with a Swagger UI page.
  • Templates: HTML templates embedded at compile time, escaped by default, checked before the server starts.
  • Data layer: an opt-in SQLite package with reflective CRUD, a query builder, transactions and migrations.
  • Real time: server-sent events with per-channel fan-out, heartbeats and bounded queues.
  • Operations: bounded memory and connections, read and write deadlines, graceful shutdown on SIGINT and SIGTERM.
