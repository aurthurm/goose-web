Getting started

Goose Web is a package. Your program's root file declares it, the Goose compiler fetches and builds it, and the result is an ordinary executable.

Requirements

  • The Goose compiler. Goose Web is tested with upstream runtime 4d3da949e563; the pinned source revision is in docs/ci.md. Put goose on your PATH, or set GOOSE=/path/to/goose for the scripts.
  • A C compiler (gcc or clang). The compiler builds the runtime and your program's C with it.
  • git, which the compiler uses to fetch a package. Linux is the tested platform.

Start from the starter

The starter is a small project with routes, middleware, JSON, a template, OpenAPI and an end-to-end test script. The generator copies it and writes the package import for you.

python3 scripts/new_project.py my-api ../my-api --source /path/to/goose-web
cd ../my-api
goose run server.goose -- 8080     # serve on port 8080
python3 test.py                    # build, call every route, stop

Leave out --source to write the release form (aurthurm/goose-web@v0.6.0), which needs the tag to exist on GitHub. The starter README describes the files.

Declare the package

A program that uses Goose Web declares it in its root file, the one you pass to goose. Only the root file declares packages. The source decides which version you get:

SourceUse it when
import goose_web from "aurthurm/goose-web@v0.6.0";Release builds. A tag is a fixed version.
import goose_web from "github.com/aurthurm/goose-web@3f2c1a9";A commit. The most reproducible pin.
import goose_web from "https://git.example.com/you/goose-web.git@v0.6.0";Any other git host.
import goose_web from "../goose-web";A checkout you are developing. Edits apply on the next build.
Before v0.6.0 is tagged, the GitHub forms stop at goose fetch with Remote branch v0.6.0 not found. Use the local checkout form. The checkout form was built and run as a consumer; the commit and other-host forms follow the Goose packaging guide and are not yet exercised against this repository.

Then the compiler does the rest:

goose fetch program.goose      # optional: download everything the root file declares
goose build program.goose      # compile, linking the package's C
./program 8080

Fetched packages and their native builds live under ~/.goose. Deleting that directory loses nothing a build does not make again.

The SQLite package

The SQLite layer is a second package, goose_web_db, that lives in the db/ directory of the repository. A program that uses it declares both, from the same checkout or version:

import goose_web from "../goose-web";
import goose_web_db from "../goose-web/db";

It links libsqlite3, so install libsqlite3-dev to build it. Programs that do not import goose_web_db need no SQLite library.

Your first route

Save this as server.goose, with the import line from above, and run it:

import goose_web from "../goose-web";
import std;
import os;

struct Greeting { message: u8[..64] }

fn app(c: web::Ctx&) {
    request_id(c) { c.logger() {
        c.routes() {
            c.get("/hello/:name") {
                let name = c.param("name");
                guard name.len <= 56 else {
                    c.fail(web::HTTP_UNPROCESSABLE_CONTENT, "name_too_long", "Name must be at most 56 bytes");
                    return;
                }
                c.json(Greeting { message: str("Hello, ", name) });
            };
        };
    }};
}

fn main() {
    let config, ok, error = web::config_from_args(args());
    if !ok { abort(error); }
    let started = web::run(config) { c => app(c) };
    if !started { abort("server failed"); }
}
goose run server.goose -- 8080
curl http://127.0.0.1:8080/hello/Ada
# {"message":"Hello, Ada"}

Stop the server

With config.handle_signals = true, Ctrl+C or SIGTERM stops accepting connections and drains open ones for a grace period of five seconds by default. The starter sets it. Signal handling is off by default, so the example above exits at once on Ctrl+C; set the flag before web::run to get the drain.
