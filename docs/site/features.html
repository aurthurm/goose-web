Templates

Templates are bytes embedded into the program at compile time. embed_file("views/list.html") reads the file relative to the source that calls it, so a missing file is a compile error. Pages share a layout: the page's blocks fill the layout's slots, and {{> content}} places the page body. Partials come from a registry built once at startup, and check_template validates a page, its layout and its partials before the server starts:

struct Todo { id: i64, title: u8[..64], done: bool }
struct ListPage { meta: web::PageMeta, todos: Todo[..32] }

var views = web::templates();

fn main() {
    web::add_template(views, "nav", embed_file("views/_nav.html"));
    let valid, problem = check_template<ListPage>(embed_file("views/layout.html"), embed_file("views/list.html"), views);
    if !valid { print(problem[..]); abort("views are not valid templates"); }
    // ... web::run as usual
}

fn app(c: web::Ctx&) {
    c.routes() {
        c.get("/") {
            c.html_page(views, embed_file("views/layout.html"), embed_file("views/list.html"),
                ListPage { meta: web::page_meta(c, "Todos"), .. });
        };
    };
}
TagOutput
{{name}}the value, HTML-escaped
{{{name}}}the value, unescaped. Only for trusted text
{{meta.title}}a field of a struct field (dotted names)
{{#name}}...{{/name}}, {{^name}}...{{/name}}the body when a bool field is true or false
{{#each name}}...{{else}}...{{/each}}the body once per element, or the else part when the array is empty
{{@index}}, {{@count}}, {{#@first}}, {{#@last}}loop position and flags inside each
{{$name}}...{{/name}}a block: a page defines it, a layout fills its slot from it
{{> name}}, {{> content}}a partial from the registry with the current data; the page body in a layout
{{! text }}a comment, dropped from the output

Flash messages (c.flash(kind, message)) live in the signed session and show once on the next page, through web::page_meta, so a redirect after a form carries its result. Escaping covers element content and quoted attributes. Put untrusted text in {{name}}, never in {{{name}}} or inside a script or style element. The templates must be valid UTF-8.

Sessions

A session is a small signed key/value store kept in a cookie. The middleware loads it before the routes run and writes the cookie back only when the store changed:

const SESSION_SECRET = "...";   // at least 32 bytes, from configuration: never commit a real key

fn app(c: web::Ctx&) {
    session(c, web::SessionConfig { secret: SESSION_SECRET }) {
        c.routes() {
            c.post("/login") {
                if !c.session_set("user", "alice") { c.fail(web::HTTP_CONFLICT, "session_full", "Session full"); return; }
                c.no_content();
            };
            c.get("/me") { c.text(c.session_get("user")); };
            c.post("/logout") { c.session_clear(); c.no_content(); };
        };
    };
}

The store holds up to 16 entries, with keys up to 32 bytes and values up to 256 bytes. Cookies default to gw_session, HttpOnly, Path=/, SameSite=Lax, a one-day Max-Age, and an optional secure flag (set it under HTTPS).

Signed is not encrypted. The payload is readable by the client, so store identifiers and small flags, and keep anything sensitive on the server. Signing stops forgery but not replay: a copied cookie stays valid until its max_age ends, even after session_clear() on another request. Rotating the secret signs everyone out.

CSRF

csrf(c, secret, check_origin) protects unsafe methods (POST, PUT, PATCH, DELETE) with the double-submit pattern. Safe methods pass and receive a token cookie. Unsafe methods must echo the token in an X-CSRF-Token header or a csrf_token form field, or get 403 csrf_failed:

c.get("/form") {
    csrf(c, CSRF_SECRET) {
        c.html(str("<form method=post><input type=hidden name=csrf_token value=\"", c.csrf_token(),
                   "\"><button>Save</button></form>"));
    };
};
c.post("/form") { csrf(c, CSRF_SECRET, true) { c.text("saved"); }; };

With check_origin set, an Origin (or, without one, a Referer) must name the same host as the request's Host. The CSRF cookie has no Secure attribute in this version, so serve forms over HTTPS. Multipart forms are not parsed; send the token in the header from script in that case.

Authentication

PBKDF2-HMAC-SHA256 password hashes (600000 iterations by default, constant-time verification), HTTP Basic and Bearer middleware that store the verified user for c.auth_subject(), and HMAC-signed tokens with expiry. The token format has no algorithm field, so it is not JWT: nothing in it can be used to pick a weaker check.

fn check_login(user: const u8[:], password: const u8[:]) -> bool {
    return user == "alice" && web::verify_password(password, ALICE_HASH);
}
c.get("/admin") {
    c.basic_auth("Admin", check_login) { c.text(c.auth_subject()); };
};

Redirects to request-supplied targets go through c.redirect_local, which accepts only local paths. The full design and the threat model are in docs/security.md in the repository.

OpenAPI

web::openapi(c, info) { c.routes() { ... } } serves an OpenAPI 3.1 document at /openapi.json and a Swagger UI page at /docs. The document is generated from the same routes block: annotations placed before a route describe it, and they do nothing when the server handles a normal request.

web::openapi(c, web::OpenApiInfo { title: "Todo API", version: "1.0.0", description: "A small todo service." }) {
    c.routes() {
        web::summary(c, "Create a todo");
        web::accepts<TodoInput>(c);                 // requestBody, application/json
        web::returns<Todo>(c, web::HTTP_CREATED);   // response schema
        c.post("/todos") { /* ... */ };

        web::summary(c, "List todos");
        web::query_params<ListParams>(c);          // one optional query parameter per field
        web::returns_list<Todo>(c, web::HTTP_OK);
        c.get("/todos") { /* ... */ };
    };
};

Fields are required unless listed by a hook in the struct's namespace:

fn web::optional_fields(v: TodoInput&) -> const u8[:] { return "completed"; }

Struct fields become schemas with their width-based bounds; u8[..N] becomes a string with maxLength. The error envelope is documented for 400, 404, 405, 415, 422 and 500 on each operation. Constraints beyond a type's width (for example limit between 1 and 8) are not expressible yet, so say them in the summary.

SQLite

The SQLite layer is opt-in: import goose_web_db and link libsqlite3. It maps structs to tables with reflection, uses bound parameters for every value, and offers a small query builder, transactions and migrations.

struct Todo { id: i64, title: u8[..200], completed: bool }
fn web::db_table(v: Todo&) -> const u8[:] { return "todos"; }

var database = default<web::Db>();
guard web::db_open(database, "build/app.db") else { abort(web::db_error(database)); }
web::create_table<Todo>(database);

var item = Todo { id: 0, title: "Write docs", completed: false };
let id, ok = web::insert(database, item);            // a zero key lets SQLite assign the rowid
let row, found = web::find_row<Todo>(database, id);
let open = web::count<Todo>(database, web::where_eq(web::query(), "completed", false));
web::db_close(database);
  • Integers and booleans are INTEGER, floats are REAL, and u8[..N] is TEXT. Reads are checked: an out-of-range value is an error, never a silent truncation.
  • transaction(db) { ... } commits when its block returns true and rolls back otherwise.
  • migrate(db, steps) applies append-only steps, recording the version in schema_version.
  • Every call runs on the reactor thread. Keep statements short, index the columns you filter on, and do not hold a select open across slow work.

The sqlite-todos example is a complete Todo API with file persistence and restarts.

Server-sent events

A route starts an event stream with c.sse(channel). Any code on the reactor (a tick, an event handler, another route) can publish to that channel, and every subscribed stream receives the event:

var control = default<web::ServerControl>();

fn tick() {
    // One event to every stream on channel 1; the result counts the streams it was accepted for.
    web::sse_publish(control, 1, "time", "12:00:00");
}

fn app(c: web::Ctx&) {
    c.routes() {
        c.get("/events") { c.sse(1); };
    };
}

fn main() {
    var config = web::server_config();
    config.handle_signals = true;
    let started = web::run_with(config, control, app, tick, web::ignore_lifecycle);
    if !started { abort("server failed"); }
}
  • Streams send a heartbeat comment every 15 seconds by default, and a stream that falls behind by more than 256 KiB is closed while the others carry on.
  • Streams use HTTP/1.1 GET only, and do not count toward max_requests. At most 32 are open by default.
  • At shutdown each stream receives an event: close and a clean end of body.

The sse-clock example adds a browser page that uses EventSource.

Scheduler and background jobs

A bounded scheduler runs periodic and one-shot tasks from the tick, on the reactor, with monotonic times and a documented catch-up rule: a late periodic task runs once and skips the intervals it missed.

var sched = web::scheduler();

fn tick() {
    web::due(sched) { id => run_task(id) };
    web::hint_wakeup(sched, control);
}

fn main() {
    assert(web::every(sched, 1, 30000));   // every 30 seconds
    // ...
}

CPU-heavy or blocking work goes to a job pool of worker threads. Jobs are pure Goose, so a worker may not call the framework's C (sockets, the clock, SQLite, crypto); the compiler rejects that. A handler submits a job and gets a correlation id, or 0 when the queue is full, which becomes a 503. The tick drains the replies, and web::job_stop joins the workers at shutdown.

  • At most queue_limit jobs are in flight, so memory is bounded.
  • A job that aborts ends only its worker: the job is reported as lost and the worker is started again.
  • The jobs example computes prime counts, announces each result on an event stream, and drops old results on a 30-second schedule.

Custom TCP protocols

web::tcp_serve runs a nonblocking loop for protocols that are not HTTP. Handlers receive open, data, writable and closed events, and send with web::tcp_send, which refuses output past a bounded queue:

var control = default<web::TcpControl>();

fn tick() {}

fn on_event(net: web::TcpControl&, ev: web::TcpEvent) {
    match ev {
        Data d => { if !web::tcp_send(net, d.conn, d.bytes) { web::tcp_close(net, d.conn); } },
        _ => {},
    }
}

fn main() {
    var config = web::tcp_config();
    config.handle_signals = true;
    let started = web::tcp_serve(config, control, on_event, tick);
    if !started { abort("server failed"); }
}
  • Each connection's queue is bounded. Reads pause at half the limit and resume as the peer drains it, so a slow peer cannot grow memory.
  • Line and length-prefixed framing helpers keep partial messages between events, with a size limit per message.
  • web::tcp_connect opens outgoing connections in the same loop, so a server can act as a proxy.
  • Shutdown flushes queued output and sends FIN before closing, so a stopping server does not cut off a reply in flight.

The examples are tcp-echo, tcp-chat and tcp-proxy. The TCP loop runs in its own process beside any HTTP server; see the TCP section of the API reference.
